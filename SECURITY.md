# Security policy

## Supported version

Security fixes apply to the latest revision on the default branch.

## Report a vulnerability

Use GitHub private vulnerability reporting from the repository **Security** tab when it is available. If the private reporting button is unavailable, open an issue that asks the maintainer for a private contact channel. Do not include vulnerability details in that issue.

Include in the private report:

- the affected skill and section;
- the unsafe behavior or instruction;
- a minimal reproduction;
- the possible effect;
- a suggested correction, if available.

Examples include credential exposure, command injection, unsafe cloud changes, and instructions that bypass approval boundaries.

Do not include active credentials, personal data, or third-party private information in a report. Please allow time for assessment before public disclosure.
